# Coding Standards

## TypeScript

- Strict mode enabled
- No `any` types - use proper typing or `unknown` (enforced by ESLint `@typescript-eslint/no-explicit-any`)
- Define interfaces for component props
- Derive types instead of duplicating them: `z.infer<typeof projectSchema>` for project content
- Use type inference where obvious, explicit types where helpful

## React

- Functional components only (no class components)
- Keep components focused - one job per component
- Don't use `useEffect` to compute values derivable from props
- Components get data as props from the page; they never read content files themselves

## Next.js

- Server Components by default. This site is static: every page is prerendered at build time.
- Only use `'use client'` when needed (theme toggle, Projects menu, scroll spy, Motion reveals), and push it as far down the tree as possible.
- `/projects/[slug]` uses `generateStaticParams` and `export const dynamicParams = false`. Unknown slugs 404.
- `params` is a Promise; `await` it.
- No API routes, Server Actions, middleware/proxy or runtime data fetching. If a feature seems to need one, stop and ask.
- Use `next/image` for every screenshot (`sizes` set, `priority` only on the project page cover).
- Use `next/link` for internal links. External links (live sites, GitHub, LinkedIn) use a plain `<a target="_blank" rel="noopener noreferrer">` with a visible external-link icon.
- Metadata through the `metadata` export / `generateMetadata`, never hand-written `<head>` tags.

## Content

- **Projects come only from `content/projects/*.mdx`**, loaded through `src/lib/content/projects.ts`. Never hard-code a project's name, URL, colors or text in a component or page.
- Every frontmatter field is validated with the Zod schema in `src/lib/content/schema.ts`. Invalid content fails the build with a message naming the file and field.
- Files starting with `_` (like `_template.mdx`) are ignored by the loader.
- `draft: true` projects show in `npm run dev` and are excluded from production builds.
- Site-wide text and links (name, bio, email, LinkedIn, GitHub, toolbox, How I build steps, hero code card) live in `src/config/site.ts`.
- Project copy is written for recruiters: plain English, short sentences, concrete facts. No claims that aren't true in the project's repo.

## Tailwind CSS v4

**CRITICAL**: We are using Tailwind CSS v4, which uses CSS-based configuration.

- **DO NOT** create `tailwind.config.ts` or `tailwind.config.js` files (those are for v3)
- All theme configuration is done in CSS using the `@theme` directive in `src/app/globals.css`
- Dark mode is class-based (next-themes), so `globals.css` must declare `@custom-variant dark (&:where(.dark, .dark *));`
- Theme colors use the shadcn variable names plus our extras; the mapping is in `context/mockup/README.md`. Never use raw hex values in components.
- **Project accent colors are the one exception**: they come from content, so they're set as CSS variables on the project's wrapper (`style={{ "--project": p.accent, "--project-2": p.accent2 }}`) and used through Tailwind (`text-(--project)`, `bg-(--project)/15`). This is the only allowed inline `style`. Don't name them `--accent`: that's shadcn's hover color.
- Fonts are loaded in `layout.tsx` with `next/font/google` and exposed as `font-display`, `font-sans`, `font-mono`.

## Animation (Motion)

- Reveal-on-scroll and hover lift only. No animation that blocks reading or delays content.
- Respect `prefers-reduced-motion`: reveals become instant, the tech strip stops.
- Content must be visible without JavaScript (reveal starts from `opacity: 0` only after hydration, or use CSS that falls back to visible).

## File Organization

- Components: `src/components/[area]/ComponentName.tsx` where area is `layout`, `home`, `project` or `shared`
- `src/components/ui/` is generated by shadcn. Add or update components with the shadcn CLI; keep hand edits minimal.
- Pages: `src/app/page.tsx`, `src/app/projects/[slug]/page.tsx`
- Content loading and schema: `src/lib/content/`
- Site config: `src/config/site.ts`
- Scripts that run outside Next.js: `scripts/`
- Project content: `content/projects/<slug>.mdx`; images: `public/projects/<slug>/`

## Naming

- Components: PascalCase (`ProjectCard.tsx`)
- All other files: kebab-case (`check-content.ts`), except Next.js reserved names (`page.tsx`, `layout.tsx`, `opengraph-image.tsx`)
- Project slugs and image folders: kebab-case (`ez-rentals`)
- Functions: camelCase
- Constants: SCREAMING_SNAKE_CASE
- Types/Interfaces: PascalCase (no prefix)

## Styling

- Tailwind CSS for all styling; shadcn/ui components where they fit (dropdown menu, button)
- No inline styles except the project accent variables (see above)
- Light and dark mode via `next-themes` (follows the system by default)
- Mobile first: design for 375px, then scale up. 16px side gutter on phones. No horizontal page scroll at any width.
- Tap targets at least 44px

## Accessibility

- One `h1` per page, headings in order
- Every screenshot has meaningful `alt` text (`coverAlt` in content); decorative images use `alt=""`
- Icon-only buttons have an `aria-label`
- Everything works with the keyboard, with a visible focus ring (including the Projects menu)
- Text contrast at least 4.5:1 in both themes, including text on project accent colors
- Color is never the only signal (status has text next to the dot)

## Images

- Covers are 1280×800 PNG (or WebP) in `public/projects/<slug>/cover.png`
- Captured from the live site with Playwright, light mode, no cookie banners or dev overlays
- Keep each image under 500 KB

## Testing

- Unit tests use [Vitest](https://vitest.dev/) (`vitest.config.mts`, Node environment)
- Test the content layer (`src/lib/content`): schema rules, sorting, draft filtering, slug lookup, prev/next. Not components; UI is checked in the browser.
- Co-locate tests as `name.test.ts`; tests use fixture MDX files in `src/lib/content/__fixtures__/`, not the real content
- `npm test` runs once; `npm run test:watch` watches

## Code Quality

- No commented-out code unless specified
- No unused imports or variables
- Keep functions under 50 lines when possible
- `npm run lint`, `npm test` and `npm run build` must pass before committing
