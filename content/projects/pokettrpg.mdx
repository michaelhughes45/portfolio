highlights:
  - Turn-based multiplayer battles kept in sync by polling, with no WebSocket server
  - Damage from the Smogon calculator that competitive Pokémon players use, run on the server
  - Separate player, DM and admin roles, each with its own permissions
problem: Running a Pokémon-themed tabletop game means tracking HP, PP, status effects, turn order and damage formulas by hand, which slows every battle to a crawl.
solution: The DM sets up campaigns, encounters and NPCs; players manage trainers, Pokémon and items. The app resolves damage, status and turn order, while movement stays on the physical table with miniatures.

challenges:
  - title: Multiplayer without WebSockets
    text: Each battle is a state machine (move submission, speed-ordered targeting, end of round) stored in one database document. Clients poll it every few seconds, which runs on free hosting, and a phone that drops off simply picks up the current state on its next poll.
  - title: Pokémon data without a giant import
    text: Instead of seeding every species up front, data is fetched from PokeAPI the first time it appears in a game and cached, with an admin button to refresh an entry.
  - title: Keeping the table in the game
    text: The app deliberately doesn't track board position. Players choose targets based on the miniatures in front of them, and the server resolves each move as soon as its target is chosen.
